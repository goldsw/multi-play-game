# B 작업지침서

## 담당 배정 · 2026-11-12

내가 B 파트를 담당함.

1. 승리 처리
2. 브로드캐스팅(백엔드)
3. 씬 컨트롤
4. 캐릭터 스킬·데미지·스턴 처리

아래는 「독버섯 폭탄 주의보」 4인 서바이벌의 이전 첫 빌드 계획을 참고용으로 기록한 내용임. 담당 범위는 위 배정을 기준으로 함. [A 작업지침서와 공통 경기 상태 계약](./multiplayer-work-guide-a.md)

## 1. 첫 빌드 기준

- 맵 1개와 동일한 성능의 큐브 4개로 제작함. 슬롯별 색상으로 구분함. 버섯 전달, 폭발 탈락, 다음 보유자 지정, 최후 1인 결과까지 구현함.
- 조작은 우선 WASD 이동으로 검증함. 점프 채택 여부는 별도 결정으로 두고, 채택 시 공중 접촉과 카메라 동작을 함께 정의함.
- 즉사 장애물, 아이템, 고유 스킬, 재화·상점은 첫 판 검증 뒤 순차 착수함. 아래 판정 우선순위는 첫 빌드용 제안이며 A와 합의한 뒤 적용함.

## 2. 작업 순서

1. **경기 규칙** — 입력으로 현재 상태, 이번 틱의 접촉 후보, 호스트 시간을 받는 규칙 코드를 작성함. 네트워크 없이 테스트할 수 있게 구성하고 실제 경기에서는 호스트가 실행함.
2. **전달과 폭발** — 첫 보유자를 생존자 중 정함. 만료 전 유효한 접촉에서 틱당 한 명에게 전달함. 동시 접촉은 거리 우선, 거리가 같으면 슬롯 순서로 결정함. 전달할 때 기존 폭발 시각은 유지함. 접촉과 만료가 겹치면 폭발을 먼저 판정함.
3. **스턴과 재접촉** — 새 보유자에 스턴을 적용함. 스턴 중 이동과 전달을 막고, 스턴이 풀려도 기존 접촉이 한 번 해제된 뒤 새 접촉에서 전달하도록 함. 스턴 중에도 폭발 타이머는 진행함.
4. **탈락과 종료** — 폭발 시 보유자의 순위를 확정함. 생존자가 2명 이상이면 새 보유자를 정하고 새 타이머를 시작함. 1명이면 우승·결과 상태로 전환함. 탈락 플레이어는 관전하며 이동 입력이 경기 결과에 영향을 주지 않음.
5. **맵과 HUD** — 회색 박스 맵에 스폰 위치 4개를 배치함. 대기 인원, 버섯 보유자 표시, 내 탈락·관전 상태, 최종 우승자와 내 순위를 표시함. 버섯 남은 시간은 화면에 표시하지 않음.

## 3. A를 기다리지 않고 HUD 개발하기

- [공통 경기 상태 계약](./multiplayer-work-guide-a.md#1-b와-먼저-합의할-계약)에 맞춰 에디터에서 테스트용 상태를 순서대로 공급함.
- **상태 1** · 대기 단계, 3명 연결 → 대기 인원 `3/4` 표시.
- **상태 2** · 경기 중, 보유자 2번, 나 생존 → 2번 큐브에 버섯 표시.
- **상태 3** · 경기 중, 보유자 3번, 나 탈락, 내 순위 4위 → 버섯 표시가 3번으로 이동하고 나는 관전으로 전환.
- **상태 4** · 종료, 우승자 1번, 내 순위 4위 → 우승자와 내 순위 표시.
- 이후 A가 같은 상태 형식을 NGO에서 받아 공급함. HUD에 세션 접속 코드가 필요하지 않으므로, 통합 단계에서는 데이터 공급기를 연결하고 화면 전환을 다시 확인함.

## 4. 파일과 AI 작업 범위

- [공통 데이터·매니저·기능 구조](./multiplayer-architecture.md)에 따라 `Data`, `Managers`, `Features`로 나눔. B는 경기·HUD 매니저, 전달·폭발·스턴·순위 규칙, 각 화면을 책임별 스크립트로 작성함.
- B가 경기 규칙, 테스트 맵, HUD·관전·결과 프리팹을 담당함. 네트워크 시작 씬과 플레이어 프리팹 변경이 필요하면 A와 작업 순서를 합의함.
- 커밋·업로드는 [공통 틀별 완료 기준](./multiplayer-work-guide-a.md#5-커밋업로드할-틀)에 맞춰 진행함. 세부 기능은 이슈의 체크 항목으로 관리하고, 해당 틀이 연결돼 동작하면 커밋·push와 PR 리뷰를 진행함.
- B는 접속 틀의 상태 계약을 검토한 뒤 테스트 데이터로 규칙과 화면을 개발함. 경기 진행 틀과 화면·복귀 틀에서는 A와 실제 네트워크 연결까지 확인함.
- AI 요청 예시 · “버섯 만료와 접촉이 같은 틱이면 폭발 우선, 여러 접촉이면 한 명에게만 전달하는 규칙을 검토해줘. 네트워크 없이 재현하는 경계 사례를 만들어줘. HUD 상태 계약과 A가 담당하는 씬·프리팹은 변경 범위에서 제외해줘.”
- AI 구현 요청에 “데이터는 값 보관, 매니저는 실행 순서와 상태 반영, 기능 스크립트는 한 책임만 담당” 조건을 함께 전달함. 규칙 스크립트가 네트워크 호출이나 HUD 갱신까지 실행하지 않는지 리뷰함.

## 5. PR 완료 조건

- 4인 상태에서 전달 → 스턴 → 폭발 → 보유자 재지정 → 최후 1인 확정이 한 판에서 이어짐.
- 두 사람이 동시에 닿아도 보유자는 한 명임. 만료와 접촉이 같은 틱이면 이전 보유자가 탈락함. 스턴이 끝날 때 기존 접촉이 유지되면 연속 전달되지 않음.
- 에디터 테스트용 상태로 대기·보유자 변경·내 탈락·결과 화면을 각각 확인함. 최종 통합에서 동일한 전환을 네트워크 상태로 확인함.
- 정상 탈락은 관전으로, 연결 중단은 안내와 메인 복귀로 이어짐. 최종 결과에서 우승자와 내 순위가 호스트 판정과 일치함.
