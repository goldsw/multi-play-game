# A 작업지침서 — Relay·NGO와 Unity 통합

대상은 「독버섯 폭탄 주의보」의 4인 최후 생존 서바이벌 첫 빌드임. 이동은 각 플레이어의 클라이언트가 계산함. A는 위치 동기화와 호스트의 경기 판정 연결, 확정된 결과 전달을 담당함. [B 작업지침서](./multiplayer-work-guide-b.md)

## 1. B와 먼저 합의할 계약

첫 PR에서 아래 이름과 값의 의미를 확정함. 이 계약이 합의되면 A의 네트워크 작업과 B의 규칙·화면 작업을 병렬로 진행함.

- **경기 단계** · `Lobby → Loading → Playing → Finished`. 연결 종료는 화면에 별도 사유로 전달함. `Loading`은 씬과 플레이어 준비를 기다리는 단계임.
- **공유 경기 상태** · 단계, 참가자 슬롯과 연결·생존·스턴 상태, 현재 버섯 보유자 슬롯, 최종 우승자 슬롯, 플레이어별 확정 순위를 전달함. 보유자·우승자·순위가 아직 없으면 미정 값으로 처리함.
- **로컬 화면 정보** · 내 슬롯은 각 클라이언트가 별도로 받음. 슬롯은 한 세션에서 유지하는 게임용 ID임. NGO 연결 ID와의 매핑은 A가 관리함.
- **이동과 판정** · 각 클라이언트가 자기 플레이어의 입력과 이동을 처리하고 위치를 호스트에 전송함. A가 호스트에서 수신한 위치를 기준으로 접촉 후보를 모아 현재 틱과 함께 B의 규칙 코드에 전달함. B의 규칙 코드가 반환한 경기 상태를 A가 동기화함.
- **HUD 연결** · HUD는 처음 열릴 때 전체 상태를 한 번 받고, 이후 상태가 바뀔 때 새 상태를 받음. B의 에디터용 테스트 데이터와 A의 실제 네트워크 데이터는 같은 형식을 사용함. 초기 상태 없이 변경 알림만 기다리는 흐름은 피함.
- **공유 범위** · 호스트만 숨은 폭발 시각과 실제 판정용 상태를 관리함. 버섯 표시는 보유자 슬롯을 기준으로 갱신함.

## 2. 작업 순서

1. **방 생성·입장** — 호스트가 세션을 만들고 참가 코드를 표시함. 게스트 3명이 코드로 입장함. 잘못된 코드, 만석, 중복 클릭, 연결 실패를 UI가 표시할 수 있게 사유를 넘김. [Unity 세션 참가](https://docs.unity.com/en-us/mps-sdk/join-session)
2. **경기 시작·스폰** — 호스트 포함 4명이 연결된 경우에만 호스트 시작 요청을 승인함. 시작 이후 신규 참가를 차단함. NGO 씬 전환 뒤 4명 모두 로딩과 스폰을 마치면 `Playing`으로 전환함. 로딩 중 이탈이나 시간 초과 시 중단 사유를 보여줌.
3. **이동·판정 연결** — 각 클라이언트가 자기 큐브를 즉시 움직이고 위치를 동기화함. 원격 큐브는 수신한 위치를 보간함. 호스트는 받은 위치를 기준으로 접촉을 모아 B의 경기 규칙을 호출함. 각 클라이언트의 이동 코드는 호스트가 확정한 스턴·탈락 상태를 적용함.
4. **결과·복귀** — 경기 중 게스트 이탈이나 호스트 종료 시 남은 플레이어에게 사유를 표시하고 메인으로 복귀시키는 안을 첫 빌드 기본값으로 사용함. 대기 중 게스트 이탈은 빈 슬롯으로 처리함. 정상 경기 종료는 우승자와 순위를 보여준 뒤 메인 복귀로 이어짐. [Relay 연결 종료](https://docs.unity.com/ugs/en-us/manual/relay/manual/disconnection)
5. **통합** — B의 HUD에 실제 상태 공급기를 연결하고 스폰 직후, 버섯 전달, 탈락, 결과 화면을 함께 확인함. 네트워크 종료 콜백이 겹쳐도 복귀 전환은 한 번만 처리함.

## 3. 파일과 AI 작업 범위

- [공통 데이터·매니저·기능 구조](./multiplayer-architecture.md)에 따라 `Data`, `Managers`, `Features`로 나눔. A는 세션 조율, 연결, 스폰, 이동, 접촉 수집, 상태 동기화를 각각의 책임으로 구현함.
- A가 세션·전송 설정, 네트워크 시작 씬, `NetworkManager`, 네트워크 플레이어 프리팹을 담당함. 경기 상태 계약과 공용 씬 전환을 바꾸는 PR은 B가 검토함.
- 커밋·업로드는 아래의 틀이 연결돼 동작하는 시점에 진행함. 각 틀의 PR에 변경한 씬·프리팹과 테스트 인원, 재현 절차를 기록함. 세부 작업은 GitHub 이슈의 체크 항목으로 관리함.
- 공통 흐름은 GitHub 이슈에 틀의 완료 조건 작성 → 틀 단위 브랜치 → 통합 동작 검증 → 커밋·push → 상대 개발자 PR 리뷰 → `main` 병합으로 운영함. 같은 씬·프리팹은 한 번에 한 명이 수정함.
- AI 요청 예시 · “현재 설치된 Unity·MPS·NGO 버전을 기준으로 호스트와 게스트의 연결 종료 흐름을 검토해줘. 세션 코드와 상태 계약을 유지하고, 세션 관련 파일만 수정 범위로 삼아줘. 정상 종료와 강제 종료의 재현 절차를 적어줘.”
- AI 구현 요청에 “데이터는 값 보관, 매니저는 실행 순서와 상태 반영, 기능 스크립트는 한 책임만 담당” 조건을 함께 전달함. 네트워크와 이동·경기 판정·화면 갱신이 한 스크립트에 섞이지 않았는지 리뷰함.

## 4. PR 완료 조건

- 호스트 1명과 게스트 3명이 코드로 입장하고 같은 플레이어 목록과 맵을 확인함. 3명일 때 시작이 거부되고 4명일 때 1회만 시작됨.
- 모두 같은 버섯 보유자와 생존자 목록을 확인함. 각자 입력 즉시 자기 큐브가 움직이고, 다른 화면에서도 이동이 동기화됨. 호스트의 스턴·탈락 판정이 해당 클라이언트의 이동에 반영됨.
- 대기 중 게스트 이탈, 로딩 중 이탈, 호스트 강제 종료 뒤 각 화면의 복귀 결과를 확인함. 복귀 후 새 방을 만들거나 참가할 수 있음.
- Multiplayer Play Mode로 4인 기본 흐름을 반복함. 통합 PR에서는 PC 두 대 이상을 사용하고, 가능한 경우 서로 다른 네트워크에서 실제 Relay 접속까지 확인함. [Unity 멀티플레이 테스트 도구](https://docs.unity.com/en-us/multiplayer/netcode/networking-utilities)

## 5. 커밋·업로드할 틀

1. **접속 틀** — 공통 경기 상태 계약, 방 생성·코드 참가, 4인 시작·스폰이 연결됨. A가 구현하고 B가 상태 형식과 참가자 표시를 검토함.
2. **이동·충돌 틀** — 각자 Rigidbody 이동, 위치 동기화, 벽 충돌, 플레이어끼리 길 막기가 함께 동작함. A가 주도하고 B가 버섯 판정용 접촉 정보 형식을 검토함.
3. **경기 진행 틀** — 접촉 수집부터 버섯 전달·스턴·폭발·탈락·최후 1인까지 호스트에서 일관되게 처리됨. B가 규칙을 구현하고 A가 실제 4인 동기화를 연결함.
4. **화면·복귀 틀** — 대기·버섯 표시·관전·결과 HUD가 실제 경기 상태를 표시하고, 정상 종료와 이탈 후 메인 복귀가 동작함. B가 화면을 구현하고 A가 접속 상태와 복귀 흐름을 연결함.
